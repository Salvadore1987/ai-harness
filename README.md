# Harness

Локальный AI-агент для терминала. Работает с моделями Ollama, написан на Java 25, Spring Boot 4.1
и Spring AI 2.0. Собирается в GraalVM native image и стартует за 0.05–0.15 с.

## Возможности

- **Чат в терминале** — потоковый вывод, режим размышлений модели, отмена генерации по Ctrl+C.
- **Одиночный запрос** — `-p "вопрос"` печатает ответ в stdout и завершается.
- **Сессии** — каждый диалог сохраняется, его можно продолжить позже.
- **Автоматическое сжатие истории** — когда контекст заполняется, старая часть заменяется
  сводкой.
- **Файлы в запросе** — `@путь` прикладывает файл из рабочей директории.
- **Агентный режим** — модель сама читает и правит код, выполняет команды и скачивает страницы.
- **MCP** — подключение инструментов внешних MCP-серверов.

## Требования

- **GraalVM 25** (Oracle GraalVM или CE) — для сборки бинарника. Для разработки и тестов
  достаточно любого JDK 25.
- **Ollama** с моделью: `ollama pull qwen3.5:27b`.

## Сборка

```bash
./gradlew build                             # компиляция, тесты и проверки качества
./gradlew :harness-bootstrap:nativeCompile  # бинарник: около 70 с и до 7 ГБ памяти
ln -s "$PWD/bin/harness" ~/.local/bin/harness
```

Для разработки можно запускать на JVM без сборки образа:

```bash
./gradlew :harness-bootstrap:bootJar
java --enable-native-access=ALL-UNNAMED -jar harness-bootstrap/build/libs/harness.jar
```

На macOS первый запуск свежесобранного бинарника занимает около 2 с: система проверяет новый
исполняемый файл.

## Запуск

```bash
harness                                              # интерактивный режим (REPL)
harness -p "Объясни, что такое CAP"                  # один запрос, ответ в stdout
harness -p "Объясни, что такое CAP" > cap.md         # ответ в файл, размышления — в консоль
harness --mode agent -p "Что делает Calc.add?"       # агент сам читает файлы
harness --mode agent -p "Исправь Calc.add и запусти тесты"
harness list                                         # установленные модели
harness ps                                           # модели, загруженные в память Ollama
```

### Опции

| Опция | Назначение |
|---|---|
| `--model <тег>` | Модель на старте |
| `--cwd <каталог>` | Рабочая директория |
| `--resume [ID]` | Продолжить последнюю сессию директории или указанную |
| `--mode chat\|agent` | Режим работы |
| `--no-think` | Выключить режим размышлений |
| `--verbose` | Статистика токенов и полный вывод инструментов |
| `-p`, `--print <запрос>` | Один запрос без REPL; код выхода 0 или 1 |
| `--help`, `--version` | Справка и версия |

Подкоманды `list [префикс]` и `ps [префикс]` печатают таблицу моделей и завершаются. `ps`
дополнительно показывает размер, долю GPU, окно контекста и время до выгрузки.

### Команды REPL

| Команда | Действие |
|---|---|
| `/help` | Список команд |
| `/exit` | Выход (также Ctrl+D или дважды Ctrl+C на пустой строке) |
| `/clear` | Начать новую сессию; текущая сохраняется |
| `/sessions` | Сохранённые сессии этой директории |
| `/resume [id]` | Продолжить сессию; без id — последнюю |
| `/purge` | Удалить сессии этой директории, кроме текущей |
| `/compact` | Сжать историю вручную |
| `/context` | Сколько контекста занято |
| `/save [файл]` | Сохранить последний ответ в файл |
| `/model [имя]` | Сменить модель; без имени — список установленных |
| `/list [префикс]` | Установленные модели |
| `/ps [префикс]` | Модели, загруженные в память Ollama |
| `/think [on\|off]` | Режим размышлений |
| `/mode [chat\|agent]` | Режим работы |
| `/tools [префикс]` | Инструменты агента |

`@путь` прикладывает файл из рабочей директории, Tab дополняет путь. Многострочный ввод — `\` в
конце строки или Alt+Enter.

## Сессии

Сессии хранятся в `~/.harness/sessions/<id>.jsonl`. Когда история занимает 80 % окна модели,
старая часть заменяется сводкой. Фактическое окно читается из `ollama ps`. Последние сообщения,
умещающиеся в четверть окна, остаются дословно.

Последний ответ сохраняется в файл командой `/save [файл]`. Без имени файл называется
`answer-<время>.md`. В режиме `agent` можно попросить словами: «сохрани этот текст в notes.md».
В обоих случаях текст копируется из истории дословно, модель не генерирует его заново.

## Агентный режим

Включается командой `/mode agent` или опцией `--mode agent`. Модели доступны инструменты:

| Инструмент | Назначение |
|---|---|
| `read_file`, `list_dir`, `glob`, `grep` | Чтение и поиск по файлам |
| `write_file`, `edit_file` | Создание и правка файлов |
| `run_command` | Выполнение команды в оболочке |
| `http_fetch` | Загрузка веб-страницы |
| `save_answer` | Сохранение последнего ответа в файл |

Каждый вызов виден в консоли, например `⏺ read_file(src/Main.java)`, с первыми строками
результата. `edit_file` показывает цветной diff.

Как ведёт себя агент:

- Инструменты выполняются без подтверждения.
- Относительные пути считаются от `--cwd`.
- `run_command` запускает `zsh -c` с пустым stdin. По таймауту (120 с) всё дерево процессов
  завершается.
- Ход останавливается после 25 запросов к модели без финального ответа.
- При `-p` с перенаправленным выводом вызовы инструментов идут в stderr, в stdout — только ответ.

### Модели без tool calling

Такие модели работают через текстовый протокол. Инструменты описываются в системном промпте,
модель пишет вызов блоком ```` ```tool ```` в конце ответа, а harness прячет его из вывода.
Режим выбирается по префиксу имени модели в `~/.harness/config.yml`. Ключи с точкой
записываются в квадратных скобках:

```yaml
harness:
  tool-call-modes:
    "[codellama]": text-json
    "[qwen3.5]": native
  default-tool-call-mode: native
```

## MCP

Инструменты внешних MCP-серверов доступны агенту под именами `mcp__<сервер>__<инструмент>`.
В `/tools` имя сервера показано во второй колонке.

stdio-серверы описываются в `~/.harness/mcp.json` в формате Claude Desktop:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/me/proj"]
    }
  }
}
```

Streamable HTTP-серверы и их заголовки задаются в `~/.harness/config.yml`. Значения заголовков
лучше брать из переменных окружения; пустой заголовок не отправляется:

```yaml
spring:
  ai:
    mcp:
      client:
        streamable-http:
          connections:
            remote: { url: https://mcp.example.com, endpoint: /mcp }
harness:
  mcp:
    headers:
      remote:
        Authorization: "Bearer ${REMOTE_MCP_TOKEN:}"
```

Серверы подключаются в фоне после запуска, REPL их не ждёт. Первый агентный ход или `/tools`
дожидается подключения. Недоступный сервер пропускается с предупреждением
`⚠ MCP-сервер «…» недоступен: …`, остальные инструменты продолжают работать. Список
инструментов фиксируется на всю сессию.

## Конфигурация

Значения задаются переменными окружения или в `~/.harness/config.yml`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HARNESS_MODEL` | `qwen3.5:27b` | Модель на старте |
| `HARNESS_OLLAMA_BASE_URL` | `http://localhost:11434` | Адрес Ollama |
| `HARNESS_NUM_CTX` | `65536` | Окно контекста; применяется при загрузке модели |
| `HARNESS_COMPACT_THRESHOLD` | `0.8` | Доля окна, при которой история сжимается |
| `HARNESS_KEEP_TAIL_SHARE` | `0.25` | Доля окна под сообщения, которые остаются дословно |
| `HARNESS_CHARS_PER_TOKEN` | `3.5` | Символов на токен для оценки |
| `HARNESS_KEEP_ALIVE` | `30m` | Сколько Ollama держит модель в памяти |
| `HARNESS_TEMPERATURE` | `0.2` | Температура |
| `HARNESS_THINKING_ENABLED` | `true` | Режим размышлений на старте |
| `HARNESS_THINKING_DISPLAY` | `stream` | `stream` — текст рассуждений, `summary` — одна строка |
| `HARNESS_THINKING_PERSIST` | `false` | Писать рассуждения в файл сессии |
| `HARNESS_AGENT_MAX_ITERATIONS` | `25` | Запросов к модели в одном агентном ходе |
| `HARNESS_AGENT_MAX_PARSE_FAILURES` | `2` | Нечитаемых вызовов подряд до остановки |
| `HARNESS_TOOLS_MAX_OUTPUT_CHARS` | `8000` | Предел вывода инструмента для модели |
| `HARNESS_TOOLS_SHELL` | `/bin/zsh` | Оболочка для `run_command` |
| `HARNESS_TOOLS_COMMAND_TIMEOUT` | `120s` | Таймаут `run_command` |
| `HARNESS_TOOLS_HTTP_TIMEOUT` | `30s` | Таймаут `http_fetch` |
| `HARNESS_DEFAULT_TOOL_CALL_MODE` | `native` | Режим вызова инструментов по умолчанию |
| `HARNESS_MCP_REQUEST_TIMEOUT` | `30s` | Таймаут запроса к MCP-серверу |
| `HARNESS_HOME` | `~/.harness` | Сессии, история ввода, логи, `config.yml`, `mcp.json` |

Логи пишутся только в `~/.harness/logs/harness.log`: консоль занята диалогом.

## Тесты

```bash
./gradlew test                                         # unit, WireMock и ArchUnit, без Ollama
./gradlew test -PincludeTags=live                      # против локальной Ollama с qwen3.5:27b
./gradlew :harness-bootstrap:test -PincludeTags=native # собирает образ и проверяет бинарник
```

## Модули

| Модуль | Содержимое |
|---|---|
| `harness-application` | Ядро без фреймворков: модели, порты, use case'ы, мапперы |
| `harness-infrastructure` | Адаптеры: CLI, консоль, хранение сессий, инструменты, MCP-клиент |
| `harness-adapter:ollama` | Провайдер Ollama (Spring AI) |
| `harness-adapter:anthropic` | Провайдер Claude (Anthropic Java SDK), пока каркас |
| `harness-bootstrap` | Точка входа, конфигурация Spring, сборка `bootJar` и native image |
