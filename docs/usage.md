# Запуск и использование

Пошаговое руководство: от установки до работы в агентном режиме. Сборка — в
[build.md](build.md), запуск готового бинарника — в [run.md](run.md), справочник по опциям и
переменным окружения — в [README](../README.md).

## 1. Подготовка

1. Установите [Ollama](https://ollama.com) и запустите её (`ollama serve` или приложение Ollama).
2. Скачайте модель по умолчанию:

   ```bash
   ollama pull qwen3.5:27b
   ```

   Подойдёт и другая модель — её тег передаётся через `--model` или `HARNESS_MODEL`.
3. Для сборки из исходников нужны JDK 25 и GraalVM 25 (см. [build.md](build.md)); готовому
   бинарнику JDK не нужен.

Проверка, что Ollama доступна и модель на месте:

```bash
curl -s http://localhost:11434/api/tags | grep qwen3.5
```

## 2. Сборка и установка

Сборка и её настройка описаны в [build.md](build.md), установка и запуск готового бинарника —
в [run.md](run.md). Коротко:

```bash
./gradlew :harness-bootstrap:nativeCompile
ln -s "$PWD/bin/harness" ~/.local/bin/harness
```

## 3. Первый запуск

Перейдите в каталог проекта, с которым хотите работать, и запустите REPL:

```bash
cd ~/projects/my-app
harness
```

Строка-баннер показывает модель, режим, состояние размышлений и рабочую директорию. Вводите
вопрос и нажимайте Enter — ответ печатается по мере генерации.

| Действие | Как |
|---|---|
| Многострочный ввод | `\` в конце строки или Alt+Enter |
| Остановить генерацию | Ctrl+C во время ответа |
| Выйти | `/exit`, Ctrl+D или дважды Ctrl+C на пустой строке |
| Список команд | `/help` |

## 4. Режимы работы

### Чат (по умолчанию)

Модель отвечает без доступа к файлам. Чтобы показать ей файл, приложите его через `@путь`
(Tab дополняет путь):

```text
› Найди ошибку в @src/main/java/Calc.java
```

### Агент

В агентном режиме модель сама читает и правит файлы, выполняет команды и скачивает страницы.
Включается флагом `--mode agent` или командой `/mode agent` прямо в REPL:

```text
agent› Почему падает CalcTest? Исправь и запусти тесты
⏺ read_file(src/test/java/CalcTest.java)
⏺ edit_file(src/main/java/Calc.java)
⏺ run_command(./gradlew test)
```

Каждый вызов инструмента виден в выводе, `edit_file` показывает diff. **Инструменты выполняются
без подтверждения**, поэтому запускайте агента в каталоге под git, чтобы изменения можно было
просмотреть (`git diff`) и откатить. Список доступных инструментов — `/tools`.

### Одиночный запрос

`-p` выполняет один запрос, печатает ответ в stdout и завершает работу с кодом 0 или 1 —
удобно для скриптов:

```bash
harness -p "Объясни, что такое CAP"
harness --mode agent -p "Что делает Calc.add?"
harness -p "Напиши сообщение коммита для этого diff: $(git diff)"
harness --mode agent -p "Сколько TODO в проекте?" > answer.txt  # вызовы инструментов уйдут в stderr
```

## 5. Сессии

Каждый диалог сохраняется в `~/.harness/sessions/<id>.jsonl`.

| Задача | Как |
|---|---|
| Продолжить последнюю сессию этой директории | `harness --resume` или `/resume` |
| Продолжить конкретную | `harness --resume <id>` или `/resume <id>` |
| Посмотреть сохранённые | `/sessions` |
| Начать новую, сохранив текущую | `/clear` |
| Сколько контекста занято | `/context` |
| Сжать историю вручную | `/compact` |

Когда история занимает 80 % окна модели, старая часть автоматически заменяется сводкой.

## 6. Модель и размышления

```text
/model                 список установленных моделей (то же, что /list)
/list [префикс]        установленные модели; * — текущая
/ps [префикс]          модели в памяти Ollama: размер, доля GPU, окно контекста, время до выгрузки
/model <тег>           переключиться на другую установленную модель
/think off             отключить режим размышлений (быстрее)
```

То же при запуске: `harness --model <тег> --no-think`. Списки без входа в REPL —
`harness list` и `harness ps`. `--verbose` добавляет статистику
токенов и полный вывод инструментов.

## 7. Настройка

Значения задаются переменными окружения или в `~/.harness/config.yml`; полная таблица — в
[README](../README.md#конфигурация). Частые случаи:

```bash
HARNESS_OLLAMA_BASE_URL=http://gpu-box:11434 harness   # Ollama на другой машине
HARNESS_NUM_CTX=32768 harness                          # меньше окно — меньше памяти
HARNESS_THINKING_DISPLAY=summary harness               # рассуждения одной строкой
```

Подключение MCP-серверов описано в [README](../README.md#mcp).

## 8. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `harness executable not found` | Бинарник не собран: `./gradlew :harness-bootstrap:nativeCompile` |
| Ошибка соединения с Ollama | Ollama запущена, адрес совпадает с `HARNESS_OLLAMA_BASE_URL` |
| Модель не найдена | `ollama pull <тег>`, тег совпадает с `--model` |
| Агент повторяет нечитаемые вызовы | Модель без нативного tool calling — задайте ей `text-json` в `tool-call-modes` (см. README) |
| `⚠ MCP-сервер «…» недоступен` | Команда из `~/.harness/mcp.json` запускается вручную; остальные инструменты работают |
| Первый запуск на macOS около 2 с | Система проверяет новый бинарник, следующие запуски быстрые |

Подробности ошибок — в `~/.harness/logs/harness.log`: в консоль логи не пишутся.
